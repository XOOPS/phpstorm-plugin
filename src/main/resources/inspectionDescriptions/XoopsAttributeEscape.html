getVar() is not an escaper — XOBJ_DTYPE_OTHER / SOURCE fields come back raw and attribute context needs ENT_QUOTES regardless.

Context is decided from the string literal that precedes the accessor in the same concatenation ('<a href="' . $obj->getVar('url')). PHP code such as $title = …, array keys and link text are never attribute context. Inside a URL query ('?src=' . …) the fix uses rawurlencode() on the raw value. The fix wraps the complete call expression, receiver included, and is idempotent.

The DTYPE comes from the class's initVar(); for an untyped receiver, from the one declaration of the key in the module's class/ / src/, else in core kernel/. Numeric DTYPEs are never reported; TXTBOX, TXTAREA, URL and EMAIL are already htmlspecialchars()'d (ENT_QUOTES) by the default and 'e' formats. The attribute fix is offered only for a raw value (OTHER, SOURCE, format 'n'): when the DTYPE cannot be resolved the finding is a weak note without a fix, because wrapping an already-escaped value prints &amp;#039;.
