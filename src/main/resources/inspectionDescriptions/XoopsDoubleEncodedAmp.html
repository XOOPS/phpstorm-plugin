header('Location: …') and ModuleAdmin::addItemButton() take a raw URL: renderButton() escapes it and header() sends it as is. A literal &amp; in that string reaches the server as a parameter named amp;…, so the token check fails. The fix writes &. A URL printed into HTML is left alone.

redirect_header() (and the helper's redirect()) also take a raw URL, but turn &amp; back into & for their meta refresh, so the browser requests the same URL either way: there it is a weak note, and the same fix gives identical output.
