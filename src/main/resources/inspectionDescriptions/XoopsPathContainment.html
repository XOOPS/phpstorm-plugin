strpos($path, $base) === 0 or str_starts_with($path, $base) on a filesystem path is a prefix test, not containment: /safe/../outside/secret starts with /safe, and /uploads2/x starts with /uploads.

Not reported: a realpath()'d path (directly, through a local, or behind a failure ternary such as $root !== false ? realpath(…) : false, through a str_replace() that only swaps separators, or a private method's parameter whose every caller in the class passes one) against a base ending in DIRECTORY_SEPARATOR or '/' — that is containment; a literal needle ('/', 'www.', 'ldaps://') — a shape test; a prefix strip for display (str_starts_with($p, $root . '/') ? substr($p, strlen($root)) : $p); a URL, a referer, or a prefix test inside a function that handles URLs (named for URLs or redirects, taking a URL, or calling parse_url()). A resolved path against a base without a separator gets its own message.

Report only. The fix is realpath() on both sides and a comparison against the directory plus a separator, placed where the path is final.
