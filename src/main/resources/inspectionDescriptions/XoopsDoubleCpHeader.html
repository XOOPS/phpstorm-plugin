A second xoops_cp_header() on one request breaks the admin menu.

The inspection reads the sibling admin_header.php: only when that file really calls xoops_cp_header() is the page's own call a duplicate. Modules whose header file only loads cp_header.php keep their call. Without an admin_header.php, a later call duplicates the page's own first call only when that first call is a top-level statement; one call in each branch of an if / else renders once.

The delete fix is offered only for the admin_header.php case, and not when $xoopsOption (for example template_main) changes on the way to the second call. A duplicate of the page's own call (the system admin pages: one on top, another in an error branch) is reported without a fix: the page has used the first theme in between, so deleting the second call is not output-neutral. The fix is never part of "Fix all".
