fetchArray() / fetchRow() / fetchBoth() on a handle that no isResultSet() check dominates.

Recognised guards: a positive check in the enclosing if / while condition (including while ($db->isResultSet($r) && $row = …)), an early-exit if (!$db->isResultSet($r)) or if (!$r) in a preceding statement, until the handle is reassigned. An early exit may also end in break / continue; a check in the same expression guards too (isResultSet($r) && … ? fetch($r) : false, isResultSet($r) && … && fetch($r)), and a handle the function receives as a parameter is the caller's to guard. A fetch inside if (!$db->isResultSet($r)) { … } is a reversed condition and gets its own message.

The fix inserts an early return that keeps the enclosing function's failure contract ([], 0, false, null) — never a throw.
