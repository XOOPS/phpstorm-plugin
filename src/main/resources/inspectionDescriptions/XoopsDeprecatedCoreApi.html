Core APIs the 2.7.4 tree marks @deprecated (list generated from the real class/, kernel/ and include/ docblocks) plus pre-2.5 idioms that still surface in old modules: XoopsTree, XoopsComments, Snoopy, XOBJ_DTYPE_UNICODE_*, xoops_getModuleOption(), the sanitizer's makeTboxData4*() family, Smarty 2 method names on XoopsTpl, and PHP 4 constructor calls (parent::XoopsObject()).

PhpStorm's own deprecation inspection needs the core in the project; this one works on a standalone module and says what to use instead. A rename fix is offered only where the replacement takes the same arguments (destoryVars → destroyVars, parent::XoopsObject() → parent::__construct(), assign_by_ref → assignByRef …). The UNICODE dtypes are never renamed: they decide how stored rows are decoded.
